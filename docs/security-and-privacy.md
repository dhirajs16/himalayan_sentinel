# Security and privacy

- Passwords use salted scrypt; seed values come only from environment. No production defaults are embedded. Development seeds refuse production and preserve existing hashes.
- Random hashed access/refresh tokens, 15-minute access, eight-hour refresh, refresh rotation, HttpOnly SameSite cookies, origin checks for refresh and session revocation. Enable secure cookies and HTTPS for deployment. Never persist access tokens in localStorage.
- Server role and jurisdiction checks protect moderation, incidents, evidence, exports and alerts. Admins administer systems; assigned officials authorize incidents and publication. Sensitive decisions, exports, evidence access and account changes are audited without passwords, tokens, contact details or image content.
- Database-backed rate limits apply to login, reporting, tracking and AI requests. Keys hash the connection address; arbitrary forwarded IP headers are ignored. Shared NAT limits can affect several citizens. Production edge rate limiting and trusted proxy configuration are still required.
- Multipart requests require Content-Length and cap the total body at 6 MB. Images are capped at 5 MB, checked against MIME and actual decoder format, and limited in pixel count. Random filenames discard supplied names. Original bytes are private; authorized display uses a newly encoded JPEG with EXIF removed. SVG and arbitrary files are rejected.
- Contact details, original evidence and exact observation coordinates are never present on public report/map endpoints. Unguessable tracking codes reveal only status/timestamps. Staff must manually redact identifying content before entering public alert text. Automatic semantic redaction is not claimed.
- Consent and an accuracy declaration are required. Guest verification is a development mock, visibly labelled, and reporting is unavailable in production until a real verification provider is implemented. CORS is restricted to configured origins; security headers and no-store apply to sensitive routes.
- SQLAlchemy binds values. Evidence paths are generated internally. React escapes rendered text; no raw user HTML is rendered. Provider errors become safe, generic messages and explicit fallback modes. No DHM scraping or bypass of licence acceptance occurs.

Before production: configure an actual verification provider, TLS and secure cookies, database least privilege, encrypted private object storage, managed backups/retention and deletion process, central audit monitoring, malware scanning, accessibility review, incident-response policy, scoped official onboarding, validated thresholds and a transactional notification queue. SQLite and a single scheduler are intended for local demonstrations. Record jurisdiction decisions according to the real authority structure before operational use.
